# نصب و آپدیت محافظت‌شدهٔ Nessus

[English](README.md) · [معماری](docs/ARCHITECTURE.md) · [بازیابی](docs/RECOVERY.md) · [محدودهٔ آزمون](docs/TESTING.md)

ابزاری مستقل برای نصب بومی Nessus از بستهٔ رسمی و آپدیت افزونه‌ها با پشتیبان کامل رمزگذاری‌شده. هدف، جلوگیری از روش‌های مخربی است که هنگام شروع سرویس، نشانگر خوراک یا پایگاه داده را حذف یا بازنویسی می‌کنند.

**این پروژه لایسنس، افزونه یا باینری Nessus را منتشر نمی‌کند.** دریافت آپدیت آنلاین به ثبت معتبر متعلق به استفاده‌کننده و دسترسی به سرویس Tenable نیاز دارد. ابزار، ثبت نامعتبر را دور نمی‌زند و وعدهٔ رفع همهٔ خطاهای محصول را نمی‌دهد.

## کامپایل افزونه چه فایده‌ای دارد؟

افزونه‌ها آزمون‌ها، وابستگی‌ها و اطلاعات تشخیص را تعریف می‌کنند. Nessus آن‌ها را پردازش می‌کند و پایگاه داخلی آمادهٔ بارگذاری می‌سازد. وجود فایل‌های دانلودشده به‌تنهایی به معنی قابل‌استفاده‌بودن آزمون‌ها نیست؛ موتور باید مجموعه را بارگذاری کند. بنابراین این ابزار شمار افزونه‌های فعال، خانواده‌ها و تطبیق مجموعهٔ نصب‌شده با مجموعهٔ بارگذاری‌شده را از API می‌خواند.

آماده‌شدن پایگاه افزونه به‌تنهایی ثبت محصول، دریافت آپدیت جدید یا صحت یک اسکن واقعی روی هدف را ثابت نمی‌کند. ابزار هیچ اسکن هدفی اجرا نمی‌کند.

از نسخهٔ `0.2.2`، فرمان `doctor` در خروجی `localReuse` مشخص می‌کند که مجموعهٔ کامپایل‌شدهٔ سالم باید حفظ شود؛ خطای ثبت به دانلود مجدد همان محتوا یا دستکاری نشانگر منجر نمی‌شود. تشخیص هنگام اسکن فعال هم ممکن است، اما تغییرات همچنان به نبود کار فعال و بازهٔ نگهداری نیاز دارند. [روش استفادهٔ مجدد و مرز بازیابی کش](docs/LOCAL_REUSE.md) را بخوانید. این قابلیت، انتقال خودکار کش بین نصب‌ها یا ترمیم ثبت با فایل کامپایل‌شده نیست.

## چه کاری انجام می‌دهد؟

- نصب تازهٔ بستهٔ رسمی `.deb` با SHA-256 معتبر؛ در صورت وجود نصب قبلی از بازنویسی آن خودداری می‌کند.
- بررسی HTTPS با اعتبارسنجی کامل گواهی و بررسی بومی ثبت؛ خطای واقعی را پنهان نمی‌کند.
- پشتیبان کامل از پوشهٔ متوقف‌شدهٔ نصب، شامل افزونه‌ها و اطلاعات همان نصب، با رمزگذاری AES-256 و آزمون بازگشایی واقعی.
- آپدیت فقط با فرمان بومی Nessus؛ پس از آن ۶۰ ثانیه بازخوانی پایدار و، در صورت درخواست، آزمون ری‌استارت انجام می‌شود.
- کاهش شمار افزونه، تغییر حساب‌ها یا تغییر اطلاعات اسکن و Policy را شکستِ نیازمند بررسی اعلام می‌کند.
- بازگشت صریح به پشتیبان همان نصب؛ نسخهٔ کنارگذاشته‌شده را نیز حفظ می‌کند.

نشانگر خوراک دستی ویرایش یا حذف نمی‌شود؛ مجوزهای آن مسدود نمی‌شوند؛ تنظیمات ثبت از نصب دیگری کپی نمی‌شوند. باینری یا امضای افزونه دستکاری نمی‌شود. کد پروژه عملیات حذف و پاک‌سازی ندارد؛ خود محصول می‌تواند فایل‌های خودش را هنگام آپدیت جایگزین کند، به همین دلیل پشتیبان لازم است.

## شروع استفاده

نسخهٔ نخست برای میزبان بومی Debian/Ubuntu با systemd، Python 3.12 یا جدیدتر و GnuPG آماده شده است. Ubuntu 24.04 و Debian 13 اهداف اولیه‌اند. نصب کانتینری، Windows و RPM در محدودهٔ این نسخه نیستند. بستهٔ متناسب با سیستم و هش مستقل آن را از [سایت رسمی Tenable](https://www.tenable.com/downloads/nessus) تهیه کنید.

```bash
git clone https://github.com/MiRHaDi/nessus-safe-install.git
cd nessus-safe-install
sudo python3 -m nessus_safe install \
  --package /secure-downloads/Nessus-OFFICIAL-PACKAGE.deb \
  --sha256 YOUR_VERIFIED_64_CHARACTER_SHA256
```

این فرمان فقط برنامهٔ نصب را نشان می‌دهد. پس از بررسی، همان فرمان را با `--apply` اجرا کنید. ثبت معتبر محصول و تنظیم گواهی و دسترسی شبکه از مسیر رسمی انجام می‌شود؛ ابزار صفحهٔ مرورگر باز نمی‌کند و کد فعال‌سازی دریافت نمی‌کند.

پس از آماده‌شدن محصول:

```bash
sudo python3 -m nessus_safe doctor \
  --url https://scanner.example.org:8834 \
  --ca-file /secure-ca/nessus-ca.pem
```

برای آپدیت، بازهٔ نگهداری اختصاصی برای همهٔ کاربران و زمان‌بندی‌ها در نظر بگیرید:

```bash
sudo python3 -m nessus_safe update \
  --url https://scanner.example.org:8834 \
  --ca-file /secure-ca/nessus-ca.pem \
  --maintenance-window --verify-restart
```

نام میزبان باید با گواهی تطبیق داشته باشد. رمز حساب و رمز پشتیبان به‌صورت مخفی پرسیده می‌شوند و ذخیره نمی‌شوند. رمز پشتیبان را در مدیر رمز خود نگه دارید؛ بدون آن، بازیابی ممکن نیست. برای استفادهٔ خودکار، ورودی محرمانه از file descriptor پشتیبانی می‌شود، نه از آرگومان حاوی رمز.

اسکن فعال یا وضعیت ناشناخته جلوی عملیات را می‌گیرد. دید API ممکن است همهٔ اسکن‌های خصوصی سایر کاربران را پوشش ندهد؛ `--maintenance-window` اعلام مسئولانهٔ اپراتور دربارهٔ اختصاصی‌بودن بازه است. پشتیبان‌ها در `/var/lib/nessus-safe-install/` خصوصی می‌مانند و نباید در Git قرار گیرند.

ابزار باید روی خود میزبان Nessus اجرا شود. اتصال API به `127.0.0.1:8834` محدود است؛ نام میزبانِ URL برای اعتبارسنجی TLS استفاده می‌شود. مدیریت نصب روی سرور دیگر یا اتصال صرفاً از طریق reverse proxy در محدودهٔ این نسخه نیست.

## بررسی نسخه و ارتقای خود موتور

```bash
python3 -m nessus_safe versions --current-version 10.12.4
```

این فرمان بدون دسترسی root، نسخه‌ها و هش بسته‌ها را از فهرست رسمی Tenable می‌خواند. در بررسی ۲۲ اکتبر ۲۰۲۶، نسخهٔ فهرست‌شده `10.12.5` بود؛ نسخهٔ Nessus با شمارهٔ `12.7.4` در منابع رسمی بررسی‌شده پیدا نشد. اطلاعات نسخه را برای دفعات بعد دوباره از همین فرمان بخوانید.

فرمان `update` فقط افزونه‌ها را به‌روزرسانی می‌کند. برای ارتقای موتور، فرمان جداگانهٔ `upgrade` اضافه شده است؛ ثبت معتبر، نسخهٔ مقصد مشخص، پشتیبان میزبان مستقل و آزمون اجباری ری‌استارت لازم دارد. مسیر بومی `nessuscli update --all` اجرا می‌شود؛ موفقیت فقط با خواندن نسخهٔ واقعی `nessusd -v` اعلام می‌شود. ابزار، کانال عرضه را عوض نمی‌کند و دریافت نسخه‌ای را که Tenable عرضه نکرده تحمیل نمی‌کند. [راهنمای ارتقای موتور](docs/UPGRADES.md) را بخوانید؛ بازگشت فایل‌سیستمی بین دو نسخهٔ باینری همچنان مسدود است تا وضعیت package manager ناسازگار نشود.

## محدودیت مهم

در نسخهٔ `0.2.1`، خطای دانلود `403 / Cloudflare 1010` با معرفی صحیح برنامه در درخواست برطرف شد؛ همان لینک روی همان اتصال پاسخ `200` داد. [آزمون واقعی نصب بستهٔ رسمی 10.12.5](https://github.com/MiRHaDi/nessus-safe-install/actions/runs/39688945737) روی Ubuntu 24.04، بررسی هش، جلوگیری از بازنویسی نصب موجود و حفظ فایل آزمایشی پس از ری‌استارت را گذراند. این نتیجه به معنی اثبات آپدیت آنلاینِ دارای ثبت معتبر نیست.

آزمون‌های خودکار، رمزگذاری و بازیابی واقعی روی دادهٔ ساختگی را پوشش می‌دهند. **هنوز آزمون کامل نصب و آپدیت آنلاین با لایسنس واقعی برای همهٔ نسخه‌های پشتیبانی‌شده انجام نشده است.** ابتدا روی VM آزمایشی اجرا کنید. خطای اعتبارسنجی preference، نیازمند ترمیم معتبر ثبت همان نصب است؛ reset خودکار یا جعل خوراک راه‌حل این ابزار نیست.

موفقیت دستور نصب بسته، موفقیت ثبت و آپدیت را ثابت نمی‌کند. به همین ترتیب، ثابت‌ماندن شناسهٔ مجموعه پس از آپدیت به عنوان دریافت تازه گزارش نمی‌شود. حذف یا بازنشانی خودکار داده، بازگشت کور روی کار جدید و پاک‌سازی پشتیبان انجام نمی‌شود. جزئیات کامل، روش آفلاین دارای مجوز و کدهای خروج در [راهنمای انگلیسی](README.md) و [راهنمای بازیابی](docs/RECOVERY.md) آمده‌اند.

مجوز MIT فقط برای کد و مستندات این پروژه است. محصول و افزونه‌های Tenable تابع مجوزهای خود سازنده‌اند؛ این پروژه وابسته یا مورد تأیید Tenable نیست.
